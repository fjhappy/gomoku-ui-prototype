# 五子棋 · UI 原型（数据驱动）

一个单文件、零依赖的移动端五子棋 UI 原型。双击 `gomoku-ui-prototype.html` 即可在浏览器里跑起来 —— 不需要构建、不需要后端、不需要联网。

它解决的问题不是「画一个五子棋界面」，而是：**当界面里的角色、头像、台词都由服务端下发时，前端该怎么组织，才不至于把任何一处写死。**

## 里面有什么

- **左侧**：390×844 的手机预览（棋盘 / 立绘 / 消息区 / 底部操作区 / 终局页）
- **右侧**：调试工具条 —— 切 7 个界面状态、开关坐标轴、实时编辑 MODEL 数据

## 怎么玩

1. 双击打开 HTML 文件。
2. 点「开始对局」。
3. 点棋盘上的空交点 → 出现落子预览 → 点「确认落子」走完一个回合（角色会自动应一手）。
4. **点角色的气泡** → 底部操作区原地变成输入框，可以跟角色说话。
5. 想验证「没有写死」：在右侧工具条里改 `MODEL` 的 JSON，点「应用」，界面立刻变。

## 核心设计：一切可变内容来自 MODEL

页面里没有写死的名字、头像、台词。所有会变的东西都在 `DEFAULT_MODEL` 里：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `session.viewer` | 登录态 | 当前用户（昵称、头像） |
| `session.character` | 角色资料 | 当前角色（昵称、头像） |
| `utterance.text` | 服务端生成 | 角色这一轮说的话 |
| `dialogue.*` | 本地兜底 | 服务端没下发时才用的文案表 |
| `game.*` | `GET /state` | 对局快照（棋盘、手数、状态、当前执子方） |
| `ui.*` | 硬编码 | 纯界面文案（按钮、状态词） |

头像留空时会自动用名字首字做圆形占位 —— 所以换角色是**零改动**的。

## 接自己的后端

只需要改 `GomokuAdapter` 里的三个方法：

```js
readState(instanceId)     // → GET  /state    拉取对局快照
dispatch(action)          // → POST /action   提交一个动作（落子 / 认输 / 悔棋）
reset()                   // → 重开一局，返回全新快照
say({ instanceId, text }) // → POST /say      角色对局内一句话的回应
```

`actionType` 目前有 `place_piece` / `resign` / `undo`；落子的 payload 是 `{ coordinate: "H8" }`，其余为空对象。
每次 dispatch 都带 `expectedStateVersion`，后端做乐观并发校验，版本不匹配就拒绝。

## 三条硬约束

1. **棋盘位置不许动。** 任何新增内容都不能改变棋盘的 y 坐标。做法是「固定高度的消息区 + 同一个槽位切换的操作区」，实测三态切换位移 0px。
2. **Surface 与 Expression 分离。** 棋盘只提供「现在发生了什么」（事实），角色说不说话、说什么由服务端决定（`utterance.text`）。客户端不替角色开口，服务端没给就保持安静。
3. **落子是主任务，说话是副任务。** 两者共用棋盘下方同一个槽位，不并排、不常驻。

文件内还有一份 17 条的「踩坑清单」（工具条里点「实现说明」），记录了移植到 Flutter 时最容易翻车的点：键盘顶起棋盘、棋子与网格线差半格、消息区 `flex-basis` 写成 `auto` 会把棋盘挤扁、输入框丢焦点、触点小于 24px 等等。

## 已知限制

- 纯前端原型，胜负判定和对手走子都在页面内的 `Mock` 里。对手用的是「棋型评估 + 四层搜索（minimax + alpha-beta）」：分得清活三和眠三、活四和冲四，会堵双三、会算谁先成五，单步约 100ms。
- 这只是**服务端行为的占位**。真实实现里算棋应当在服务端，客户端只负责把坐标发出去、把结果画出来。
- 「棋谱 / 复盘」不提供入口 —— 只展示「没有能力的入口宁可灰掉」这个处理方式。悔棋是可用的，同样走 `dispatch({ actionType: 'undo' })`，一次撤销一个完整回合（对手的应手 + 自己那一手）。
- 单条气泡限 2 行（为了不把棋盘挤走）；真正需要长历史时应另开半屏抽屉。
